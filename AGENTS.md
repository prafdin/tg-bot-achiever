# Инструкции для Codex

## Контекст проекта
Проект — шуточный Telegram-бот достижений для небольшого дружеского чата. Источник согласованных продуктовых требований: `PRODUCT_CONCEPT.md` в корне репозитория. Прочитай его перед проектированием и реализацией.

## Текущий этап
Концепция, декомпозиция функциональных подсистем, модели событий, контекста и жизненного цикла ачивок, механизм награждения, пользовательский веб-интерфейс и объём администрирования согласованы. Состав MVP определён в `PRODUCT_CONCEPT.md`. Детали технической архитектуры отложены. Не начинай реализацию и не выбирай стек без согласования с пользователем.

## Рабочий процесс
- Общайся с пользователем на русском языке.
- Прорабатывай проект последовательно, по одному существенному вопросу за раз. Предлагай варианты и объясняй их компромиссы; не повторяй вопросы, уже закрытые в концепции.
- Отделяй согласованные решения от предложений и открытых вопросов. Не подменяй продуктовые требования техническими предположениями.
- После согласования существенных решений актуализируй документацию. Не меняй ранее согласованные требования без явного согласия пользователя.
- Сначала предложи декомпозицию функциональных подсистем, их ответственность, входы, выходы и взаимодействия. Не углубляйся преждевременно в конкретные алгоритмы или ачивки.
- При техническом проектировании проверяй реальные ограничения Telegram Bot API и выбранных инструментов. Учитывай согласие участников, минимизацию данных, отказ от анализа, безопасность административных функций и сохранение истории награждений.
- Не вводи соревнование, публичный каталог, задания или активное участие бота в беседах. Не заменяй детерминированное награждение субъективной оценкой LLM.
- Состав MVP согласуй отдельно: полная концепция не означает, что все функции обязательны для первой версии.
