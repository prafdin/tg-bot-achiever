# Ачивки чата

Telegram-бот считает новые сообщения согласившихся участников одного чата. За 10 учтённых сообщений один раз выдаётся ачивка «Десяточка». Суточная проверка публикует сводку с новыми наградами и ссылкой на личный профиль.

## Запуск

1. Создайте отдельного бота через BotFather, добавьте его в чат и отключите Privacy Mode. Если бот уже был в группе, добавьте его заново, чтобы новая настройка вступила в силу. Для long polling у этого бота не должно быть активного webhook или другого процесса чтения обновлений.
2. В настройках Login Widget в BotFather зарегистрируйте адрес сайта и точный адрес обратного вызова `https://ваш-домен/auth/callback`. Сохраните выданные Client ID и Client Secret. Оставьте подпись RS256 по умолчанию.
3. Создайте `.env` из `.env.example`. Укажите токен бота, реквизиты OIDC, адрес сайта, ID чата и разрешённых участников. Сгенерируйте `SESSION_SECRET` командой `python -c 'import secrets; print(secrets.token_urlsafe(32))'`.
4. Настройте HTTPS-прокси для домена, направив запросы на `127.0.0.1:8000` на ВМ. При другом `ACHIEVER_PORT` используйте его. Для Caddy, установленного на ВМ, подойдёт следующий блок для домена с настроенным DNS.

```caddyfile
achiever.example.org {
    reverse_proxy 127.0.0.1:8000
}
```

5. Возьмите ID успешной сборки ветки `main` и подставьте его вместо `RUN_ID`. Выполните команды в каталоге проекта на сервере.

```sh
docker pull ghcr.io/prafdin/tg-bot-achiever:build-RUN_ID
docker tag ghcr.io/prafdin/tg-bot-achiever:build-RUN_ID tg-bot-achiever-achiever:latest
docker compose up -d --no-build
```

Образы публикуются в [GitHub Container Registry](https://github.com/users/prafdin/packages/container/package/tg-bot-achiever). SQLite находится в томе `achiever-data`.

`AWARD_TIME` задаёт локальное время проверки, `AWARD_TIMEZONE` задаёт часовой пояс. При запуске после назначенного времени бот выполнит проверку за текущую дату, если она ещё не проводилась. Чтобы приостановить сбор, установите `COLLECTION_PAUSED=1` и примените конфигурацию через `docker compose up -d --no-build`.

Для имён награждённых бот запрашивает данные участников у Telegram. Telegram гарантирует доступ к данным других участников, когда бот — администратор. Если имя недоступно, в сводке появится «Участник чата».

Подписи в профилях и списке участников задаются в `.env`, например `PARTICIPANT_NAMES='{"123456789":"Имя Фамилия"}'`. Если подпись не задана, сайт показывает «Участник» и числовой ID. Доступ определяется `ALLOWED_TELEGRAM_IDS`.

## Проверка

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install '.[test]'
python -m pytest -q
ACHIEVER_ENV_FILE=.env.example docker compose config -q
```

Сборка Docker-образа выполняется на GitHub Actions.

На ВМ откройте сайт по HTTPS и проверьте вход разрешённого участника и отказ для другого Telegram ID. Отправьте несколько сообщений при выключенном сборе, затем включите его в профиле и отправьте 10 обычных сообщений. После суточной проверки проверьте ачивку в профиле, запись в истории и одну сводку в чате. Перезапустите контейнер и убедитесь, что согласие и история сохранились и повторной выдачи нет.

Если Telegram принял сводку, но ответ потерялся, повторная попытка может продублировать сообщение в чате. Запись о выдаче в SQLite остаётся единственной.

## Выпуск версии

1. Обновите `version` в `pyproject.toml` и дождитесь успешной сборки `main`.
2. Выкатите сборку на стейдж по `RUN_ID` и проверьте её.
3. Запустите [Release](https://github.com/prafdin/tg-bot-achiever/actions/workflows/release.yml) с версией из `pyproject.toml` и тем же `RUN_ID`. Workflow публикует Git-тег `vMAJOR.MINOR.PATCH`, GitHub Release с `release.json` и тег GHCR `MAJOR.MINOR.PATCH` для исходного дайджеста.
4. Для ручной выкладки в прод используйте номер опубликованной версии в репозитории деплоя.
