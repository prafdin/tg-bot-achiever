# План реализации MVP

> Для исполнения использовать superpowers:executing-plans или superpowers:subagent-driven-development. Отмечать выполненные шаги.

**Цель.** Запустить один чат, одну постоянную ачивку и защищённую страницу личного профиля.

**Архитектура.** Один процесс обслуживает сайт, получает обновления Telegram и запускает суточную проверку. SQLite хранит согласия, учтённые действия и награждения в постоянном томе.

**Стек.** Python, Starlette, Authlib, SQLite, Telegram Bot API, Docker Compose. Существующий HTTPS-прокси или Caddy.

**Спецификация.** [PRODUCT_CONCEPT.md](../../../PRODUCT_CONCEPT.md), раздел «MVP для запуска за один день».

## Ограничения

- Один заданный чат и явный список Telegram ID для входа.
- Сбор выключен по умолчанию. Согласие меняется из личного профиля. Пауза сбора задаётся в конфигурации.
- Храним идентификаторы, факт отправки и время. Текст и медиа не сохраняем.
- Одна постоянная ачивка за 10 сообщений. Суточная проверка, одна сводка со ссылкой при новых награждениях.
- На странице профиля история отображается под актуальными ачивками.

## Проверки с учётом рисков

- Дубли обновлений и повторный запуск проверки покрываются тестами SQLite.
- События при выключенном сборе, во время паузы или до возобновления наблюдения исключаются.
- Вход и изменение согласия проверяются отдельно. В тестах есть отказ при недействительной сессии или CSRF-токене.
- Отказ Telegram при отправке оставляет сводку ожидающей. После неоднозначного таймаута повторная отправка может задублировать саму сводку, поскольку Bot API не предоставляет ключ идемпотентности для `sendMessage`. Награждения защищены уникальным ключом.
- Запуск за день предполагает доступ к ВМ, DNS и BotFather. Реальная установка и публикация проверяются отдельно.
