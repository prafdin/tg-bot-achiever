# Список обладателей ачивки

## Цель

На странице уже открытой ачивки показать, кто из доступных участников её получил. Это позволит перейти от описания ачивки прямо к профилю обладателя.

## Согласованные требования

- Показать имена обладателей в алфавитном порядке.
- Каждое имя — ссылка на профиль участника. Для текущего пользователя ссылка ведёт на его личный профиль.
- Не показывать даты получения.
- Страница ачивки остаётся за входом и открывается только после первой выдачи этой ачивки; публичный каталог не появляется.
- Брать подписи участников из конфигурации сайта, как в остальных списках.

## Подходы

1. **Имена со ссылками. Выбранный подход.** Компактно отвечает на вопрос «кто получил?» и использует существующие профили.
2. **Имена со ссылками и датами.** Даёт историю получения прямо на странице, но добавляет детали, которые пользователь не просил.

## Предлагаемая реализация

Для каждой поддерживаемой ачивки получать пары Telegram ID и даты из соответствующей таблицы награждений. В веб-слое преобразовать ID в настроенные подписи и передать отсортированный список шаблону страницы ачивки. Шаблон выводит раздел с обладателями; при отсутствии строк раздел можно не показывать, хотя условие открытия страницы обычно означает, что хотя бы одна выдача уже есть.

Список наследует действующие ограничения доступа: просмотр страницы требует входа и доступен только участникам из списка разрешённых ID. Новые данные в хранилище не добавляются.

## Не входит в объём

- Даты, количество ачивок, ранжирование и другие сравнительные элементы.
- Публичная страница или список ачивок, которые ещё никто не получил.
- Изменение механики награждения или хранения истории.
